# XMQR client 0.17.0 — validade e Will MQTT 5 (experimental)

C69/C70 acrescentam `--message-expiry-seconds` para publicação MQTT 5 e `--will-delay-seconds` para Will MQTT 5. A opção de Will exige Will configurado; ambas rejeitam MQTT 3.1.1. O padrão 3.1.1 segue disponível.

**Limites:** um novo processo do client ainda não restaura seus próprios fluxos QoS pendentes. Outras Will Properties, controle completo de fluxo, propriedades de publicação/assinatura, shared subscriptions e AUTH seguem pendentes. As fases 6A–6D estão abertas. O broker parceiro 0.19.0 grava estado v8; faça backup privado antes de atualizá-lo, pois 0.18.0 não reabre v8.

Ubuntu 26.04 amd64: verifique os SHA-256 e manifesto da prerelease, preserve configuração e segredos e instale o `.deb` numerado. Para rollback do client, pare a unidade e reinstale 0.16.0 preservando perfis. A tag Docker `latest` não é movida; este release não instala nada no WSL do operador.

Validação: gates Rust, testes unitários/wire e integração real com broker P132 e Mosquitto 2.0.22. Evidências: [C69](../../prompts/registros/C69-message-expiry-mqtt5.md) e [C70](../../prompts/registros/C70-will-delay-mqtt5.md).
